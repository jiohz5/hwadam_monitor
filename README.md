# 화담숲 티켓 모니터

`run_hwadam.bat`를 더블 클릭해 실행합니다. 기본 목표는 **2026-10-25(일), 08:00~08:20, 성인 2장·경로 2장·어린이 2장**입니다.

## 처음 설치하기

Windows, Python 3.10 이상, Microsoft Edge가 필요합니다.

```powershell
git clone https://github.com/jiohz5/hwadam_monitor.git
cd hwadam_monitor
python -m pip install -r requirements.txt
python main.py
```

`main.py`가 여러 Python 모듈을 불러오는 구조이므로 저장소 전체와 `assets/`, `data/` 폴더가 함께 필요합니다. 로고·아이콘은 프로그램에 포함되어 있습니다. 이후에는 `run_hwadam.bat`로 실행할 수 있습니다.

개인 로그인 세션, 텔레그램 토큰·채팅 ID, 감시 설정, 브라우저 프로필, 로그 및 조회 캐시는 Git에 포함하지 않습니다. 새 PC에서는 아래 사용 순서대로 로그인하고 알림 설정을 입력하세요. 화담숲 프로그램의 실행 파일은 `main.py`입니다.

## 사용 순서

1. 왼쪽 상품 보관함에서 **2026 화담숲 입장권 (10.23-11.15)** 또는 **2026 화담숲 입장권(05.12-10.22)**을 고릅니다. 각 상품은 실제 페이지의 상품명으로 표시됩니다.
2. `연결 · 알림` → `로그인 브라우저 열기`를 눌러 전용 Edge에서 NOL에 로그인합니다. 로그인 후 `로그인 세션 저장`을 누릅니다. 다음 실행부터 저장된 세션을 읽어 복원합니다.
3. `티켓 탐색` → `두 상품 목록 확보`를 누르면 두 상품의 현재 예약 가능한 날짜별 입장 회차와 모노레일 구간별 목록을 저장합니다. 이미 완전히 저장된 날짜는 건너뛰므로 중단 후 이어받을 수 있습니다. 한 날짜를 최신 목록으로 갱신하려면 달력에서 날짜를 고르고 `이 날짜 새로고침`을 누릅니다.
4. 달력에서 이용 날짜와 요일을 확인하면 입장권과 모노레일 회차가 나란히 표시됩니다. 각 시간의 개별 체크박스로 여러 회차를 선택하며 두 목록의 선택은 독립적입니다. 모노레일 구간은 두 목록 위에서 고릅니다. 각각 `전체 / 오전 / 오후`로 탐색할 수 있고 품절 회차도 선택할 수 있습니다. `08:00~08:20`은 양 끝 시각을 포함합니다. 직접 `08:00, 08:20`처럼 입력할 수도 있습니다. 오른쪽에서 권종별 수량을 정하고, `연결 · 알림`에서 봇 토큰·채팅 ID와 `알림 테스트`를 확인한 다음 `감시 시작`을 누릅니다.
5. 알림의 구매 링크를 열어 직접 예매합니다. 조건을 바꾸려면 `중지` 후 변경하고 다시 시작합니다.

홈에서 날짜·회차 탐색, 감시 조건, 회차별 현재 재고와 실시간 로그를 함께 볼 수 있습니다. 날짜·회차 탐색 영역만 스크롤되고 재고와 로그는 화면에 남습니다. 달력은 웹사이트처럼 **일~토 순서**로 표시합니다. `감시 현황` 탭이나 로그의 `크게 보기`를 누르면 같은 로그를 화면 가득 볼 수 있습니다. 로그를 위로 올려 읽는 동안에는 새 기록이 들어와도 읽던 위치를 유지하고, 맨 아래에서는 새 기록을 따라갑니다.

상품·날짜·모노레일 구간별 체크 상태는 종료 후에도 보관합니다. 달력의 점은 회차 목록이 저장된 날짜입니다. **목표 수량은 알림의 최소 조건이 아닙니다.** 수량을 1장 이상 지정한 권종 중 하나라도 구매 가능하면 알립니다. 0장으로 지정한 권종은 제외합니다. 회차의 공통 잔여 수량을 성인·경로·어린이 각각의 재고로 더하지 않습니다.

목록 확보는 실제 API가 반환한 날짜와 시간을 저장하며 임의 회차를 만들지 않습니다. 저장 시각이 표시되는 목록은 재고 보장이 아닙니다. 모노레일 탐색 목록은 당일 첫 입장과 전체 권종 기준이며, 감시할 때는 선택한 입장 시각·권종으로 다시 확인합니다. 추가구매는 해당 주문의 권종·입장 시각으로 조회합니다. 상품 이름과 예약 기간은 기본 제공되지만 최초 회차 목록 확보에는 로그인이 필요합니다.

## 두 모드

| 모드 | 설정 | 알림 조건 |
| --- | --- | --- |
| 입장권 (+ 모노레일 확인) | 상품·날짜·입장 회차·권종 수량 | 선택 권종의 입장권이 1장이라도 가능 |
| 모노레일 추가구매 | 실제 입장권 주문에서 연 추가구매 주소·같은 이용 날짜·구간·모노레일 회차 | 해당 주문으로 추가구매할 수 있는 권종이 1장이라도 가능 |

입장권 모드의 모노레일 회차 목록은 항상 탐색할 수 있습니다. 모노레일 시간을 체크하면 `알림에 모노레일 포함`이 자동으로 켜지고 선택한 시간만 함께 확인합니다. 포함 체크만 켜고 시간을 비워 두면 입장 회차마다 이후의 가까운 판매 후보 최대 8회차를 확인합니다. 각 후보에는 기준 입장 시각을 표시하며, 그 입장 회차에서 가능한 권종만 연결합니다. 모노레일이 품절이거나 조회에 실패해도 입장권 알림은 보냅니다.

추가구매 주소는 `https://leisure-web.yanolja.com/leisure/상품번호?orderGroupId=...` 형태입니다. 일반 입장권 상품 주소만으로는 주문 자격을 확인할 수 없습니다. 선택 날짜가 주문과 다르거나 권종별 목표가 추가구매 한도를 넘으면 이유를 표시합니다. 여러 입장 시각이 섞인 주문은 한 시각으로 확인되는 주문 링크를 사용하세요.

`입장 +20분 ±15분으로 찾기`를 켜면 각 입장 회차를 기준으로 모노레일 시간을 자동으로 정합니다. 예를 들어 08:00 입장은 08:05~08:35, 08:20 입장은 08:25~08:55 범위입니다. 목록의 체크 상태는 두 범위에 포함되는 실제 회차를 보여주며, 감시에서는 입장 회차별 범위를 각각 적용합니다. 이 설정에서는 모노레일 시간을 직접 수정할 수 없으며, 끄면 개별 체크 방식으로 돌아갑니다. 입장권이 가능한 회차를 발견했을 때 해당 입장 시각으로 모노레일을 함께 확인합니다.

## 결제 준비와 관리 모드

`결제 준비`에서 현재 상품·날짜·회차·권종 수량을 확인하고 선호 결제수단과 결제 전 점검 항목을 정리할 수 있습니다. `상품 페이지 열기`로 실제 페이지를 열고 결제는 브라우저에서 직접 진행합니다. 카드정보·본인인증·PIN 입력은 실제 결제창에서 수행합니다.

`관리 모드` → `관리 모드 열기`는 로컬 관리 도구를 활성화하는 화면 스위치입니다. 초기셋업 점검에서 세션 파일·저장된 회차 수·텔레그램 입력 상태를 확인하고 기존 로그인 설정이나 로그 폴더를 열 수 있습니다. 세션 파일 존재는 실제 로그인 유효성을 뜻하지 않습니다.

CGV 참고 프로그램의 테스트 종류·수량·결제 단계 구조를 화담숲에 맞췄습니다. 입장권 / 입장권+모노레일 / 추가구매, 현재 목표 수량 / 1장 부분 가용, 결제 직전 / 전체 결제(PIN까지)를 고른 뒤 `테스트 수행 (GUI)`로 화면 동선을 점검합니다. `다음 단계 확인`은 로컬 표시만 갱신하며, `테스트 종료` 또는 관리모드 닫기로 멈출 수 있습니다. 실제 결제 테스트는 사용자가 직접 진행합니다. 이 GUI에는 자동 예매·결제 실행이 연결되어 있지 않습니다.

선호 결제수단과 테스트 시나리오만 `operation_settings.json`에 저장합니다. 기존 CGV의 결제 PIN·관리자 비밀번호는 가져오지 않습니다. 일반 감시 설정과 관리모드 테스트 조건은 독립적입니다.

## 알림과 운영

- 기본 조회 주기는 10초입니다. 오류가 반복되면 대기시간을 늘립니다.
- 기본 반복 알림은 0초로, 첫 발견·품절 후 재등장·가용 수량 증가·새 권종 등장에 알립니다. 같은 상태를 주기적으로 받고 싶다면 반복 알림 시간을 10초 이상으로 설정하세요.
- 전송 실패는 성공 처리하지 않고 재시도합니다. 감시 중 30분마다 공식 NOL 계정 페이지를 거쳐 로그인 세션을 갱신하고 최신 쿠키를 저장합니다. 쿠키 파일 저장만으로 유효기간이 늘어나지는 않습니다. 성공 시 로그에 새 만료 예정 시각을 표시합니다.
- 조회 인증이 거절되면 세션을 한 번 재연결하여 다시 조회합니다. 계정 로그인 자체가 만료되어 갱신·복원 후에도 인증되지 않으면 감시를 중지하고 재로그인을 안내합니다. 현재 브라우저의 계정 로그인을 먼저 확인한 뒤 저장 쿠키를 복원합니다.
- PC와 프로그램을 켜 두고 절전 모드를 해제하세요. 전용 Edge 창을 닫으면 조회가 실패할 수 있습니다.
- 재고는 조회와 예매 사이에 바뀔 수 있습니다. 최종 구매 수량과 모노레일 탑승 가능 여부는 예매 화면에서 확인하세요.

기존 `cgv_grok_new`, `hwadam_claude`의 텔레그램 설정과 로그인 쿠키는 필요할 때 읽습니다. 저장은 이 폴더에만 합니다. 기존 봇의 명령 수신과 충돌하지 않도록 `getUpdates`를 사용하지 않습니다.

일반 설정은 `settings.json`, 봇 설정은 `helper_secrets.env`, 로그인 세션은 `session_cookies.json`과 `edge_profile/`에 저장됩니다. 회차 목록은 `catalog_cache.json`, 탐색 체크 상태는 `browse_choices.json`입니다. 주문 링크·토큰·쿠키가 들어 있는 파일은 다른 사람에게 전달하지 마세요. 진행 기록은 `logs/hwadam.log`입니다. 실행 오류는 `run_hwadam_console.bat` 또는 `logs/startup_error.log`에서 확인합니다.

`설정 저장`과 `로그인 세션 저장`은 별개입니다. 로그인 세션 저장은 날짜·회차·권종 조건을 정하기 전에도 사용할 수 있습니다. 현재 로그인이 확인되지 않으면 기존 세션 파일을 덮어쓰지 않습니다. 로그인은 `로그인 브라우저 열기`로 연 hwadam_codex 전용 Edge에서 진행하세요.

## 개발 및 검증

Python 3.10 이상과 Microsoft Edge가 필요합니다. 현재 PC의 Anaconda Python을 실행 파일에서 우선 사용합니다.

```powershell
python -m pip install -r requirements.txt
python -X utf8 -m unittest discover -s tests -v
python -X utf8 main.py --gui-smoke
python -X utf8 main.py --sync-catalog
python -X utf8 main.py --sync-catalog --resume
python -X utf8 main.py --probe --product-url https://leisure-web.yanolja.com/leisure/10323843 --date 2026-10-03 --times 09:00,09:20 --monorail --mono-times 09:20~09:38
python -X utf8 main.py --probe
```

`--gui-smoke`는 기본 크기와 최소 크기에서 버튼 배치를 검증합니다. `--sync-catalog`는 두 상품의 회차 목록을 저장합니다. `--probe`는 실제 재고를 한 번 조회합니다. 두 조회 명령은 텔레그램을 보내거나 감시 설정을 바꾸지 않습니다. 실제 조회에는 전용 Edge 로그인이 필요합니다. 드라이버는 설치된 Edge 버전에 맞춰 준비합니다. 전용 디버깅 포트는 `9444`입니다.
