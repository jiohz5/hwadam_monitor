# 화담숲 티켓 모니터

`run_hwadam.vbs`를 더블 클릭하면 명령창 없이 GUI가 기존 기본 크기로 실행됩니다. 전용 브라우저는 화면 오른쪽 40% 너비와 작업표시줄을 제외한 전체 높이로 열립니다. 실행 후에는 창 크기와 위치를 자유롭게 바꿀 수 있습니다. 기본 목표는 **2026-10-25(일), 08:00~08:20, 성인 2장·경로 2장·어린이 2장**입니다.

## 처음 설치하기

Windows, Python 3.10 이상, Microsoft Edge가 필요합니다.

```powershell
git clone https://github.com/jiohz5/hwadam_monitor.git
cd hwadam_monitor
python -m pip install -r requirements.txt
python main.py
```

`main.py`가 여러 Python 모듈을 불러오는 구조이므로 저장소 전체와 `assets/`, `data/` 폴더가 함께 필요합니다. 로고·아이콘은 프로그램에 포함되어 있습니다. 이후에는 `run_hwadam.vbs`로 실행합니다. 바탕화면에 두려면 이 파일의 **바로 가기**를 만드세요. 실행 파일 자체는 프로그램 폴더에 둡니다.

기존 `run_hwadam.bat`도 사용할 수 있으며, 실행 오류를 콘솔에서 확인하려면 `run_hwadam_console.bat`를 사용합니다. VBS 실행기는 현재 사용자 폴더의 Anaconda, PATH의 `pythonw.exe`, `pyw.exe` 순서로 Python을 찾습니다. Python을 찾지 못하면 안내창을 표시합니다.

개인 로그인 세션, 텔레그램 토큰·채팅 ID, 감시 설정, 브라우저 프로필, 로그 및 조회 캐시는 Git에 포함하지 않습니다. 새 PC에서는 아래 사용 순서대로 로그인하고 알림 설정을 입력하세요. 화담숲 프로그램의 실행 파일은 `main.py`입니다.

## 사용 순서

1. 왼쪽 상품 보관함에서 **2026 화담숲 입장권 (10.23-11.15)** 또는 **2026 화담숲 입장권(05.12-10.22)**을 고릅니다. 각 상품은 실제 페이지의 상품명으로 표시됩니다.
2. `연결 · 알림` → `로그인 브라우저 열기`를 누릅니다. 기존 로그인이 유효하면 자동으로 재사용·저장합니다. 복원에 실패하면 공식 NOL 화면의 `카카오로 시작하기`와 카카오에 저장된 계정 하나를 자동으로 선택합니다. 상품 페이지에서 NOL 인증까지 확인되면 `로그인 확인 · 세션 자동 저장 완료`가 표시되며, 별도로 저장 버튼을 누를 필요가 없습니다. 시작 시 자동으로 여는 브라우저에도 같은 흐름을 적용합니다. 저장 계정이 없거나 여러 개, 비밀번호·추가 인증·동의가 필요한 경우에는 화면과 로그 안내에 따라 직접 진행한 뒤 `로그인 세션 저장`을 누릅니다. 카카오톡 간편로그인의 계정 쿠키도 함께 저장하여 다음 실행에서 복원을 시도합니다.
3. `티켓 탐색` → `두 상품 목록 확보`를 누르면 두 상품의 현재 예약 가능한 날짜별 입장 회차와 모노레일 구간별 목록을 저장합니다. 이미 완전히 저장된 날짜는 건너뛰므로 중단 후 이어받을 수 있습니다. 한 날짜를 최신 목록으로 갱신하려면 달력에서 날짜를 고르고 `이 날짜 새로고침`을 누릅니다.
4. 달력에서 이용 날짜와 요일을 확인하면 입장권과 모노레일 회차가 나란히 표시됩니다. 각 시간의 개별 체크박스로 여러 회차를 선택하며 두 목록의 선택은 독립적입니다. 모노레일 구간은 두 목록 위에서 고릅니다. 각각 `전체 / 오전 / 오후`로 탐색할 수 있고 품절 회차도 선택할 수 있습니다. `08:00~08:20`은 양 끝 시각을 포함합니다. 직접 `08:00, 08:20`처럼 입력할 수도 있습니다. 오른쪽에서 권종별 수량을 정하고, `연결 · 알림`에서 봇 토큰·채팅 ID와 `알림 테스트`를 확인한 다음 `감시 시작`을 누릅니다.
5. 알림의 구매 링크를 열어 직접 예매합니다. 조건을 바꾸려면 `중지` 후 변경하고 다시 시작합니다.

홈에서 날짜·회차 탐색, 감시 조건, 회차별 현재 재고와 실시간 로그를 함께 볼 수 있습니다. 날짜·회차 탐색 영역만 스크롤되고 재고와 로그는 화면에 남습니다. 달력은 웹사이트처럼 **일~토 순서**로 표시합니다. `감시 현황` 탭이나 로그의 `크게 보기`를 누르면 같은 로그를 화면 가득 볼 수 있습니다. 로그를 위로 올려 읽는 동안에는 새 기록이 들어와도 읽던 위치를 유지하고, 맨 아래에서는 새 기록을 따라갑니다.

상품·날짜·모노레일 구간별 체크 상태는 종료 후에도 보관합니다. 달력의 점은 회차 목록이 저장된 날짜입니다. **목표 수량은 알림의 최소 조건이 아닙니다.** 수량을 1장 이상 지정한 권종 중 하나라도 구매 가능하면 알립니다. 0장으로 지정한 권종은 제외합니다. 회차의 공통 잔여 수량을 성인·경로·어린이 각각의 재고로 더하지 않습니다.

목록 확보는 실제 API가 반환한 날짜와 시간을 저장하며 임의 회차를 만들지 않습니다. 저장 시각이 표시되는 목록은 재고 보장이 아닙니다. 모노레일 탐색 목록은 당일 첫 입장과 전체 권종 기준이며, 감시할 때는 선택한 입장 시각·권종으로 다시 확인합니다. 추가구매는 해당 주문의 권종·입장 시각으로 조회합니다. 상품 이름과 예약 기간은 기본 제공되지만 최초 회차 목록 확보에는 로그인이 필요합니다.

## 두 모드

| 모드 | 설정 | 알림 조건 |
| --- | --- | --- |
| 입장권 (+ 모노레일 확인) | 상품·날짜·입장 회차·권종 수량 | 선택 권종의 입장권이 1장이라도 가능 |
| 모노레일 추가구매 | 실제 입장권 주문에서 연 추가구매 주소·같은 이용 날짜·구간·모노레일 회차 | 해당 주문으로 추가구매할 수 있는 권종이 1장이라도 가능 |

입장권 모드의 모노레일 회차 목록은 항상 탐색할 수 있습니다. 모노레일 시간을 체크하면 `알림에 모노레일 포함`이 자동으로 켜지고 선택한 시간만 함께 확인합니다. 포함 체크만 켜고 시간을 비워 두면 입장 회차마다 이후의 가까운 판매 후보 최대 8회차를 확인합니다. 각 후보에는 기준 입장 시각을 표시하며, 그 입장 회차에서 가능한 권종만 연결합니다. 모노레일이 품절이거나 조회에 실패해도 입장권 알림은 보냅니다.

추가구매 주소는 `https://leisure-web.yanolja.com/leisure/상품번호?orderGroupId=...` 형태입니다. 일반 입장권 상품 주소만으로는 주문 자격을 확인할 수 없습니다. 선택 날짜가 주문과 다르거나 권종별 목표가 추가구매 한도를 넘으면 이유를 표시합니다. 여러 입장 시각이 섞인 주문은 한 시각으로 확인되는 주문 링크를 사용하세요.

`입장 +20분 ±15분으로 찾기`를 켜면 각 입장 회차를 기준으로 모노레일 시간을 자동으로 정합니다. 예를 들어 08:00 입장은 08:05~08:35, 08:20 입장은 08:25~08:55 범위입니다. 목록의 체크 상태는 두 범위에 포함되는 실제 회차를 보여주며, 감시에서는 입장 회차별 범위를 각각 적용합니다. 이 설정에서는 모노레일 시간을 직접 수정할 수 없으며, 끄면 개별 체크 방식으로 돌아갑니다. 입장권이 가능한 회차를 발견했을 때 해당 입장 시각으로 모노레일을 함께 확인합니다.

## 결제 준비와 관리 모드

`결제 준비`에서 현재 상품·날짜·회차·권종 수량을 확인하고 선호 결제수단과 결제 전 점검 항목을 정리할 수 있습니다. `상품 페이지 열기`로 실제 페이지를 열고 결제는 브라우저에서 직접 진행합니다. 카드정보·본인인증·PIN 입력은 실제 결제창에서 수행합니다.

`관리 모드` → `관리 모드 열기`는 로컬 관리 도구를 활성화하는 화면 스위치입니다. 초기셋업 점검에서 세션 파일·저장된 회차 수·텔레그램 입력 상태를 확인하고 기존 로그인 설정이나 로그 폴더를 열 수 있습니다. 세션 파일 존재는 실제 로그인 유효성을 뜻하지 않습니다.

CGV 참고 프로그램의 테스트 종류·수량·결제 단계 구조를 화담숲에 맞췄습니다. 입장권 / 입장권+모노레일 / 추가구매, 현재 목표 수량 / 1장 부분 가용, 결제 직전 / 전체 결제(PIN까지)를 고른 뒤 `테스트 수행 (GUI)`로 화면 동선을 점검합니다. 이 버튼과 `다음 단계 확인`은 로컬 표시만 갱신하며, `테스트 종료` 또는 관리모드 닫기로 멈출 수 있습니다.

별도의 `테스트 결제 (브라우저)`는 로그인된 전용 Edge에서 **입장권의 첫 선택 시각과 첫 권종 하나**를 대상으로 합니다. 2026-10-16 업데이트에는 옵션·날짜 선택, 최종 결제 버튼 클릭, `NOL_MON_PIN` 읽기와 PIN 확인까지 진행하는 코드가 포함되어 있습니다. **현재 `stop_before_pay=True`와 GUI의 ‘최종 결제 미실행’ 안내가 실제 코드와 일치하지 않습니다.** 날짜 검증·완료 판정에도 미완성 부분이 있습니다. 상세 내용은 [업데이트 분석](docs/2026-10-16-update-review.md)을 확인하세요. 이번 통합에서는 실제 결제를 실행하지 않았습니다.

브라우저 테스트 중에는 감시·로그인·조건 변경을 잠그고, 진행/오류는 홈과 날짜별 로그에 기록합니다. 창을 닫으면 다음 동작 전에 중지합니다. 현재 예약 동선에는 기존 회귀 테스트와 맞지 않는 동작이 남아 있으며, 실제 NOL 화면의 날짜·수량 자동화나 결제 성공은 검증하지 않았습니다.

선호 결제수단과 테스트 시나리오만 `operation_settings.json`에 저장합니다. 기존 CGV의 결제 PIN·관리자 비밀번호는 가져오지 않습니다. 일반 감시 설정과 관리모드 테스트 조건은 독립적입니다.

## 알림과 운영

- 새 GUI 설정의 기본 조회 주기는 2초이며 허용 범위는 2~300초입니다. 저장된 설정이 있으면 그 값을 사용합니다. CLI `--probe`의 기본값은 10초입니다. 오류가 반복되면 대기시간을 늘립니다.
- 기본 반복 알림은 0초로, 첫 발견·품절 후 재등장·가용 수량 증가·새 권종 등장에 알립니다. 같은 상태를 주기적으로 받고 싶다면 반복 알림 시간을 10초 이상으로 설정하세요.
- 전송 실패는 성공 처리하지 않고 재시도합니다. 감시 중 30분마다 공식 NOL 계정 페이지를 거쳐 로그인 세션을 갱신하고 최신 쿠키를 저장합니다. 감시를 중지해도 프로그램이 켜져 있으면 5분마다 쿠키 상태를 점검하며, 30분마다 실제 로그인 갱신·저장을 수행합니다. SID가 없거나 만료되었거나 만료까지 10분 이내라면 먼저 갱신합니다. 쿠키 파일의 만료 값을 임의로 늘리지 않으며, 성공 시 로그에 서비스가 발급한 만료 예정 시각을 표시합니다.
- 대기 중 로그인 유지는 실행 30초 뒤 시작하며, 저장 세션이 있으면 재연결을 시도합니다. 로그인·목록 조회 중에는 해당 작업을 먼저 끝내고, 감시 중에는 감시 루프의 갱신을 사용합니다. 절전 후 복귀 시에는 실제 시각의 공백과 쿠키 만료를 다시 확인합니다. 실제 로그인이 확인되지 않으면 기존 저장 파일을 보존하고 홈에 재로그인을 안내합니다. 이 경우 자동 페이지 이동을 멈추며, 직접 로그인하고 `로그인 세션 저장` 또는 연결에 성공하면 다시 유지합니다.
- 조회 인증이 거절되면 세션을 한 번 재연결하여 다시 조회합니다. 계정 로그인 자체가 만료되어 갱신·복원 후에도 인증되지 않으면 감시를 중지하고 재로그인을 안내합니다. 현재 브라우저의 계정 로그인을 먼저 확인한 뒤 저장 쿠키를 복원합니다.
- PC와 프로그램을 켜 두고 절전 모드를 해제하세요. 전용 Edge 창을 닫으면 조회가 실패할 수 있습니다.
- 재고는 조회와 예매 사이에 바뀔 수 있습니다. 최종 구매 수량과 모노레일 탑승 가능 여부는 예매 화면에서 확인하세요.

기존 `cgv_grok_new`, `hwadam_claude`의 텔레그램 설정과 로그인 쿠키는 필요할 때 읽습니다. 저장은 이 폴더에만 합니다. 기존 봇의 명령 수신과 충돌하지 않도록 `getUpdates`를 사용하지 않습니다.

일반 설정은 `settings.json`, 봇 설정은 `helper_secrets.env`, 로그인 세션은 `session_cookies.json`과 `edge_profile/`에 저장됩니다. 회차 목록은 `catalog_cache.json`, 탐색 체크 상태는 `browse_choices.json`입니다. 주문 링크·토큰·쿠키가 들어 있는 파일은 다른 사람에게 전달하지 마세요. 진행 기록과 실행 오류는 한국 날짜별 `logs/hwadam-YYYY-MM-DD.log`에 누적합니다. `run_hwadam_console.bat`로 실행하면 콘솔에서도 오류를 확인할 수 있습니다.

`설정 저장`과 `로그인 세션 저장`은 별개입니다. 로그인 세션 저장은 날짜·회차·권종 조건을 정하기 전에도 사용할 수 있습니다. 현재 로그인이 확인되지 않으면 기존 세션 파일을 덮어쓰지 않습니다. 로그인은 `로그인 브라우저 열기`로 연 hwadam_codex 전용 Edge에서 진행하세요. 세션 파일에는 NOL과 카카오 계정 쿠키가 포함되며 카카오페이·다른 카카오 서비스의 개별 쿠키는 제외합니다. 프로그램이 꺼져 있는 동안에는 세션을 갱신하지 않으므로, 서비스에서 로그인을 만료·취소한 경우에는 직접 로그인이 다시 필요할 수 있습니다.

## 로그인 진단 로그

홈의 실시간 로그와 `logs/hwadam-YYYY-MM-DD.log`에 `[AUTH trace=추적ID flag=진단코드]` 형식의 기록을 남깁니다. 같은 `trace`는 한 번의 로그인 확인·복원 시도이며, 이후 API 인증 오류도 마지막 인증의 추적 ID로 연결됩니다. 정상적인 재고 조회마다 진단 로그를 반복하지 않고, 연결·대기 중 5분 점검·30분 갱신·복원·오류 시점에 기록합니다.

| 주요 플래그 | 확인할 내용 |
| --- | --- |
| `AUTH_BEGIN` | 로그인 브라우저 열기, 최초 연결, 강제 재연결, 수동 저장 중 어떤 동작에서 시작했는지 |
| `KEEPALIVE_CHECK` / `KEEPALIVE_REFRESH` / `KEEPALIVE_RESULT` | 대기 중 쿠키 상태와 점검 간격, 최초 확인·정기 갱신·만료 임박 중 어떤 이유로 갱신했는지, 실제 인증·저장까지 성공했는지. `trigger=keepalive`로 구분 |
| `SESSION_REFRESH_RESULT` | 현재 브라우저 또는 저장 파일 복원 후 실제 NOL 로그인이 확인됐는지. `sid_state`는 SID 쿠키 상태, `sid_remaining_s`는 남은 초, `kakao_cookies`는 카카오 계정 쿠키 수 |
| `COOKIE_FILE_MISSING` / `COOKIE_FILE_INVALID` | 저장 파일이 없거나 읽기·해석에 실패했는지 |
| `COOKIE_RESTORE_RESULT` | `source=saved/reference` 출처별 복원 수, 만료되어 제외한 수, 복원 거절 수 |
| `API_AUTH_REJECTED` | 조회 서버가 반환한 HTTP 상태와 알려진 인증 오류 코드 |
| `BROWSER_CONNECTION_LOST` / `AUTH_ERROR` | Edge 연결이 끊겼는지, 어떤 예외 종류와 마지막 단계에서 실패했는지 |
| `NAVIGATION_BEGIN` / `NAVIGATION_DONE` / `TAB_RECREATED` | 계정·상품 페이지 이동 중 어디까지 진행했는지, 리디렉션으로 사라진 대상 탭을 살아 있는 창에서 다시 만들었는지 |
| `AUTH_READY` / `LOGIN_REQUIRED` | 어떤 출처로 인증이 복구됐는지, 모든 복원 시도가 끝나 직접 로그인이 필요한지 |
| `KAKAO_LOGIN_BEGIN` / `KAKAO_START_CLICKED` / `KAKAO_ACCOUNT_CLICKED` | 카카오 자동 로그인 시작, NOL의 카카오 버튼 클릭, 저장 계정 선택 중 어디까지 진행했는지. 계정 이름·이메일은 기록하지 않음 |
| `KAKAO_LOGIN_READY` / `KAKAO_MANUAL_REQUIRED` | 상품 페이지에서 실제 인증이 확인됐는지, 또는 복수 계정·저장 계정 없음·추가 인증·시간 초과 등 수동 진행이 필요한 이유. 이후 `COOKIE_SAVED`가 세션 저장 완료를 뜻함 |

쿠키 존재나 SID 만료 여부만으로 서버의 최종 인증 상태를 단정하지 않습니다. 같은 추적 ID의 갱신 결과와 마지막 플래그를 함께 확인하세요. 중간에 `TAB_RECREATED`가 있어도 마지막에 `AUTH_READY`가 나오면 인증은 복구된 상태입니다. 쿠키·토큰 값, 전체 주소·주문번호, 응답 본문과 원본 예외 메시지는 진단 로그에 기록하지 않습니다. 날짜가 바뀌면 자동으로 새 파일에 기록하며, 같은 날 재실행하면 기존 파일에 이어 씁니다. 일별 파일은 자동 삭제하지 않습니다.

## 날짜별 실행 기록

로그 한 줄에는 한국 시각(`+09:00`), 중요도(`INFO`/`WARNING`/`ERROR`), 실행 식별자(`run`), 이벤트 코드(`event`)가 함께 남습니다. `MONITOR_STARTED`는 상품 ID·날짜·선택 시간·권종 수량·모노레일 범위·조회/반복 알림 주기를, `MONITOR_CHECK`와 `MONORAIL_CHECK`는 각 회차 재고·가능 권종을 기록합니다. 모노레일 조회 실패, 텔레그램 성공/실패, 재시도 단계·간격, 감시 종료 사유·조회 횟수도 구분됩니다.

GUI의 주요 상태 변경, 목록 확보, 로그인 유지, 결제 준비 설정 오류와 관리 모드 전환도 기록합니다. 백그라운드 결과는 화면 표시 전 파일에 저장하므로, 조건을 바꿔 이전 결과를 화면에서 제외하거나 창을 닫아도 발생한 작업 오류를 추적할 수 있습니다. 창을 닫으면 진행 중 작업의 마지막 기록을 정리한 뒤 로그를 닫습니다. 마지막 브라우저 조회가 35초를 넘기면 `SHUTDOWN_WAITING`을 남기고, 화면을 닫은 상태에서 조회 종료까지 기록을 계속 보존합니다. 조회 CLI와 시작 오류도 같은 일별 파일을 사용합니다.

예전 `hwadam.log`, `hwadam.log.1` 등의 원본은 삭제하지 않습니다. 이전 버전 실행을 끝낸 뒤 다음 명령으로 원본을 보존하면서 `logs/legacy/YYYY-MM-DD.log`에 날짜별로 정리할 수 있습니다. 같은 원본으로 다시 실행해도 중복 추가되지 않습니다.

```powershell
python -X utf8 -c "from pathlib import Path; from logfiles import split_legacy_logs; print(split_legacy_logs(Path('.')))"
```

로그·쿠키·프로필·개인 설정은 Git에 포함하지 않습니다.

## 개발 및 검증

`booking_test.py`, `ui_operations.py`에 이어 `model.py`, `monitor.py`의 구현도 `gui.py`에 통합했습니다. 이 네 파일은 더 이상 필요하지 않습니다. 실행은 기존 `main.py` 또는 `run_hwadam.vbs`를 사용하며, `gui.py`만으로 단독 실행하는 구조는 아닙니다. API·로그인·저장·레이아웃 모듈과 `assets/`, `data/`는 함께 필요합니다.

| 수정할 내용 | `gui.py`에서 찾을 위치 |
| --- | --- |
| 감시 조건·권종·시간·재고 판정 | `1. 감시 모델·재고 판정` / `WatchConfig`, `evaluate_round()` |
| 조회 반복·중복 알림·감시 이벤트 | `2. 감시 루프·알림` / `AlertTracker`, `MonitorRunner` |
| 브라우저 테스트 단계·버튼 선택·중단 조건 | `3. 브라우저 예약 테스트` / `run_test_booking()` |
| 결제 준비·관리 화면, GUI 시나리오 | `4. 결제 준비·관리 화면` / `OperationsUI` |
| 브라우저 테스트 시작 조건·작업 연결 | `OperationsUI.start_test_booking()` |
| 감시 버튼·선택 상태·작업 완료 처리 | `5. 설정 변환·앱 제어` / `App` |

전체 화면 배치·달력 위젯은 기존 `ui_layout.py`, `ui_widgets.py`에서 수정합니다. `ui_layout.build()`는 `gui.py`가 전달한 관리 화면 클래스를 사용합니다. 다른 모듈은 `from gui import WatchConfig`처럼 모델·감시 기능을 가져오며, `gui.py`의 연결·저장 의존성은 함수 안에서 불러와 순환 import를 피합니다. `--gui-smoke`와 테스트의 `App(..., auto_open_browser=False)`는 시작 시 브라우저 자동 연결을 예약하지 않습니다.

Python 3.10 이상과 Microsoft Edge가 필요합니다. 현재 PC의 Anaconda Python을 실행 파일에서 우선 사용합니다.

```powershell
python -m pip install -r requirements.txt
python -X utf8 -m unittest discover -s tests -v
python -X utf8 main.py --gui-smoke
python -X utf8 main.py --sync-catalog
python -X utf8 main.py --sync-catalog --resume
python -X utf8 main.py --probe --product-url https://leisure-web.yanolja.com/leisure/10323843 --date 2026-10-03 --times 09:00,09:20 --monorail --mono-times 09:20~09:38
python -X utf8 main.py --probe
```

`--gui-smoke`는 기본 크기와 최소 크기에서 버튼 배치를 검증합니다. `--sync-catalog`는 두 상품의 회차 목록을 저장합니다. `--probe`는 실제 재고를 한 번 조회합니다. 두 조회 명령은 텔레그램을 보내거나 감시 설정을 바꾸지 않습니다. 실제 조회에는 전용 Edge 로그인이 필요합니다. 드라이버는 설치된 Edge 버전에 맞춰 준비합니다. 전용 디버깅 포트는 `9444`입니다.
