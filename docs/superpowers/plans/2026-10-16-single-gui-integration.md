# GUI · 모델 · 감시 루프 통합 계획

**목표:** 사용자가 업데이트한 `gui.py`, `model.py`, `monitor.py`의 구현을 `gui.py` 하나로 통합하고 변경 사항을 분석한다.

**구조:** 통합 파일 안에서 감시 데이터/재고 판정, 감시·알림 루프, 브라우저 예약, 관리 화면, 앱 제어를 구역으로 구분한다. 다른 모듈은 `gui`에서 모델을 불러오고, 통합 파일은 연결·저장 모듈을 필요한 함수 안에서 불러와 순환 참조를 피한다.

**기준:** 현재 사용자 요청과 기존 실행 경로 `main.py` / `run_hwadam.vbs`. 최신 결제 흐름의 의미는 합치기 작업에서 임의로 변경하지 않으며, 발견한 문제를 분석 문서에 구분해 기록한다.

## 작업

- [x] 최신 세 파일의 구현을 이동하고 중복 import를 정리한다.
- [x] 운영 모듈과 테스트의 모델·감시 import를 `gui`로 변경한 뒤 두 원본 모듈을 제거한다.
- [x] 기존 관리 화면 두 번째 옵션 자동 선택을 복원하고, GUI 검증 실행에서 자동 브라우저 열기를 끈다.
- [x] 모듈별 최초 import, 오프라인 테스트 전체, 임시 배포 폴더의 GUI 시작을 확인한다. 총 158개 중 157개 통과, 기존 결제 중지 계약 불일치 1개 실패를 기록했다.
- [x] 업데이트의 기능 변화와 미완성/오류 지점을 분석 문서와 README에 정리한다.

## 검증 경계

- 실제 사용자 설정·PIN·세션을 변경하거나 결제를 실행하지 않는다.
- 임시 폴더와 가짜 브라우저를 사용한다. 실제 브라우저·네트워크 경계를 막는다.
- 기존 파일의 결제 테스트 계약 불일치와 통합으로 새로 생긴 문제를 구분한다.
- 브라우저 오른쪽 40% 배치, `NOL_MON_PIN` 보존, VBS 실행기 변경은 유지한다.
- 삭제한 모듈 없이 배포되는지와 import 순서에 따른 순환 참조를 확인한다.
