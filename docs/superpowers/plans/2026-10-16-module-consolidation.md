# GUI·관리·예약 테스트 통합 계획

사용자가 추가한 booking_test.py, gui.py, ui_operations.py의 변경사항을 확인하고 세 파일만 gui.py에 통합한다. 앞서 제안한 8개 구조는 사용자 수정 요청으로 대체됐다.

## 범위와 설계

- gui.py 한 파일에 예약 테스트, 관리/결제 준비 UI, 앱 제어를 기능별 구역으로 배치한다.
- main.py 실행 진입점과 다른 백엔드·화면 배치 파일은 유지한다.
- ui_layout.py는 App이 전달한 OperationsUI 클래스를 사용해 제거한 ui_operations.py를 import하지 않는다.
- 원본 3개는 logs/source-merge-*에 로컬 백업하고 통합 후 중복 소스 2개를 제거한다.
- 기존 cookie/settings/log/profile 경로와 파일은 변경하지 않는다.

## 변경분에서 발견한 오류

1. start_preview 선언이 사라져 GUI 초기화가 실패한다. 독립 메서드 경계를 복구한다.
2. section 표시 문자열을 내부 코드로 전달해 검증에 실패한다. app.read_config()를 사용한다.
3. 테스트의 daemon thread는 busy/lock/로그/종료 추적을 우회한다. _submit과 _emit을 사용한다.
4. 최종 결제 버튼 누락·비활성 상태도 성공 처리한다. 명확한 오류로 반환한다.
5. 테스트 helper의 stop_before_pay=False는 최종 결제를 클릭한다. 테스트 전용 계약에 맞춰 실행 전 거부한다.
6. 전체동의는 마지막 checkbox라는 추측을 제거하고 명시된 라벨이 연결된 항목만 찾는다.

## 유지하는 기능 한계

예약 테스트는 선택한 첫 시간과 첫 권종 하나를 시험한다. 날짜·수량 자동 입력은 구현되어 있지 않으므로 브라우저에서 미리 선택해야 한다고 UI에 표시한다. 이번 통합에서 실제 사이트 DOM을 추측해 날짜·수량 자동화를 새로 구현하지 않는다. 최종 결제는 호출하지 않는다.

## 실행 및 검증

1. 기존 operations 테스트로 GUI 초기화 실패를 확인한다.
2. test_booking.py의 fake driver/worker 회귀 테스트를 먼저 실행해 실패를 확인한다.
3. 세 소스 통합 및 연결 오류를 수정한다. 기존 로컬 GUI 시나리오는 브라우저 호출 없이 유지한다.
4. gui.py 내부 import와 제거한 모듈에 대한 참조/테스트 patch 경로를 갱신한다.
5. 배포 테스트는 유지되는 14개 소스만 복사한 폴더에서 외부 cwd로 GUI smoke를 실행한다.
6. 전체 suite, 두 화면 크기의 GUI smoke, 컴파일과 diff를 확인한다. 실제 예약·결제·텔레그램 전송은 검증에서 실행하지 않는다.
7. 독립 리뷰 후 변경 내용과 한계를 보고한다. 이번 요청에서 사용자 추가 소스 통합을 우선한다.
