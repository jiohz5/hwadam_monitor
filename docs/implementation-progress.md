# 구현 기록

Plan: docs/superpowers/plans/2026-10-02-hwadam-codex.md

사용자가 새 폴더 hwadam_codex에 제작을 지시했다. 기존 설계의 권종 목표와 두 모드를 보존하고 이 세션에서 직접 구현한다.

작업 환경: 상위 디렉토리는 Git 저장소가 아니며 새 프로젝트 폴더에서 작업한다. Git 전용 worktree·commit 도우미 대신 작업 기록과 실제 검증 결과를 남긴다.

Pre-flight: Task 1의 WatchConfig/Availability를 Task 2와 Task 3에서 사용한다. Task 2의 Snapshot과 Task 3의 MonitorRunner를 Task 4 GUI에 연결한다. 인터페이스 이름을 위 계획으로 통일한다.

Task 1: complete. 모듈 부재 RED 확인 후 순수 판정 및 저장 구현. unittest 14개 통과. 일반 설정에 봇 토큰을 넣지 않음.

Task 2: 구현 완료, 실응답 검증 진행 중. API 계약 테스트의 모듈 부재 RED 확인 후 21개 테스트 통과. 자체 Edge 실행과 참고 쿠키 복원을 실제로 확인했으나 참고 로그인 세션이 만료됨. 전용 브라우저 로그인 후 실제 조회 검증 필요.

Task 3: complete. monitor/telegram 모듈 부재 RED 확인 후 중복 억제, 재등장, 수량 증가, 전송 실패, 중지 후 늦은 결과 차단 구현. 30개 테스트 통과.

Task 4: GUI와 실행 도구 구현. unittest 33개, 실제 Windows GUI smoke 통과. 기본 샌드박스에서는 Tcl 런타임 초기화가 제한되어 실제 Windows 환경에서 검증했음. 화면 크기 1160×870, 기본 날짜·권종 수량 및 화면 내 실행/저장 버튼 배치 확인. 실제 알림은 테스트에서 전송하지 않음.

최종 검토: 새로운 읽기 전용 검토 에이전트가 전체 구현을 검토함. 중요 발견 4건(미확인 상태 오판, 권종 재고 증가 누락, 입장·모노레일 시각 혼합, 잘못된 모노레일 응답이 입장 알림을 차단)을 RED 회귀 테스트로 재현하고 수정했다. 모노레일 후보를 입장 시각 및 해당 권종에 연결하고 메시지에 기준 시각을 표시한다. 미확인 상태를 실제 품절과 구분해 재등장 추적을 보존했다.

공식 프런트엔드 공개 코드의 읽기 검증: 권종 조회 endpoint와 상태 필드, 모노레일의 parent group 조건, 추가구매 verification 응답 orders[].quantity 사용을 확인했다. 인증된 실제 응답 및 실제 추가구매 주문의 검증은 전용 Edge 로그인과 주문 링크가 준비된 뒤 실행해야 한다.

최종 확인: unittest 38개 통과, 생산 모듈 전체 py_compile 성공, 최종 GUI smoke 성공. 실제 Telegram 메시지는 자동 검증에서 전송하지 않았으며 GUI의 알림 테스트로 확인할 수 있다.

로그인 저장 흐름 보완: 사용자의 설명에 따라 전용 로그인 브라우저 열기 및 로그인 세션 저장 버튼을 추가했다. 기존에는 옵션 조회 헤더 캡처 성공 후에만 자동 저장했다. 수동 저장은 감시 조건과 독립적으로 현재 상품 응답의 로그인 여부를 새로 확인하고 저장한다. 미로그인·브라우저 부재는 명확히 표시하며 기존 세션 파일을 유지한다. 저장·다음 세션 복원, GUI 버튼을 통한 실제 파일 생성, 잘못된 감시 조건에서도 로그인 저장 가능한 경로를 검증했다. RED 3건 확인 후 구현, 전체 unittest 43개 및 GUI smoke·py_compile 통과.

2026-10-03 상품 탐색 개편: 실제 상품명 두 개를 사이드바에 표시하고 월별 달력, 요일, 오전·오후 필터, 체크형 복수 회차, 고정 감시 조건 카드, 감시 현황·연결 설정 화면을 구현했다. 상품·날짜·구간·추가구매 주문별 선택을 보관하며 재실행 시 복원한다. 공개 SSR 상품 정보는 data/catalog_seed.json, 인증된 실제 회차는 catalog_cache.json에 저장한다. 저장 목록은 실시간 알림 판정에 쓰지 않는다.

새 검토에서 확인한 모노레일 부모 입장 조건 덮어쓰기, 추가구매 주문 간 선택 혼합, 모노레일 조회 중 인증 만료 오표시를 수정했다. 탐색용 모노레일 목록은 당일 첫 입장·전체 권종으로 일관되게 읽고, 실시간 감시는 각 선택 입장 회차·권종으로 다시 검증한다. 추가구매 탐색에서 0장인 권종을 강제로 조회하던 문제와 구간 변경 시 입장 선택 손실도 회귀 테스트로 수정했다.

실제 수집: 저장된 세션으로 2026 화담숲 입장권 (10.23-11.15) 24일 및 2026 화담숲 입장권(05.12-10.22) 18일, 총 42일의 입장권·모노레일 3구간 목록을 확보했다. 상품별 누락 날짜 0개. 입장 회차 총 1,034개, 모노레일 포함 저장 행 총 11,900개. 두 번째 상품은 10/03 조회 시점 이후 남은 회차를 포함한다. 연결 끊김 1회 후 저장 데이터를 유지하고 남은 11일을 이어받아 오류 없이 완료했다. GUI 목록 확보도 저장 완료 날짜를 건너뛰며 개별 날짜 새로고침으로 갱신할 수 있다.

최종 검증: unittest 54개 통과, 전체 생산 모듈 py_compile, 1360×920 및 1160×740 GUI smoke 통과. 실제 Windows 화면에서 두 상품의 날짜·시간 버튼과 상품 전환 후 10/25 선택 복원을 확인했다. --probe로 실제 10/25 08:00·08:20의 품절 응답을 확인했다. 자동 검증에서 텔레그램 전송·예매·감시 시작은 하지 않았다. 실제 추가구매 주문 링크가 없어 주문별 실서비스 검증은 남아 있다.

모노레일 동시 탐색 보완: 날짜 아래 입장권·모노레일 목록을 두 열로 배치하고 모두 실제 Tk Checkbutton으로 변경했다. 모노레일 목록은 알림 포함 여부와 무관하게 탐색할 수 있으며 체크 시 알림 포함을 자동 선택한다. 날짜 새로고침도 두 목록을 함께 읽는다. 날짜·구간별 체크 상태 복원, 필터 변경 후 다중 선택 유지, 입장권 선택과 모노레일 선택 분리를 검증했다. 전체 unittest 55개 및 기본·최소 크기 GUI smoke 통과. 실제 Windows에서 10/25 입장 27회차와 모노레일 107회차의 나란한 체크박스·독립 스크롤을 확인하고 새 화면을 열어 두었다.

결제·관리모드 GUI: cgv_grok_new의 관리자 패널(초기셋업, 종류·수량·결제 단계, 테스트 수행·종료)을 읽고 화담숲용 결제 준비 및 관리 페이지를 추가했다. 사용자 지시대로 실제 결제는 구현·실행하지 않고, 결제 준비 설정과 로컬 화면 단계 미리보기만 구성했다. 관리 도구 활성화 스위치, 기존 로그인 설정 연결, 세션 파일·목록 저장 수·알림 설정 존재 여부 점검, 로그 폴더 열기를 제공한다. 결제정보·PIN·기존 관리자 비밀번호는 복사하거나 저장하지 않는다. 새 설정 파일에는 선호 결제수단 및 시나리오 enum 4개만 저장한다. UI 테스트 전체 경로에서 BrowserSession.connect/request, webbrowser.open, TelegramNotifier.send 호출이 없음을 검증했다. 감시 조건 독립성과 관리모드 닫기·중지·재시작 시 비활성화도 확인했다. 전체 58개 테스트, GUI smoke, 생산 모듈 컴파일 및 실제 결제 준비·관리모드 화면 확인 완료.
